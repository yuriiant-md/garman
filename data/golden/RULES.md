# Правила розмітки golden set

Еталон — це те, що уважна людина може прямо прочитати **в тексті `data/texts/…txt`** (не в PDF), за тими самими правилами, що й у промпті: немає в тексті → `null`, умова є, але не з дозволених варіантів → `"other"`.

**Хто розмічав.** Чернетку розмітки всіх 17 договорів (`prozorro_001–010`, `own_001–007`) підготував Claude Opus 5.5; автор перевірив кожне поле за текстом і виправив спірні значення.

## Загальні

1. **Enum, числа, дати — за змістом, крізь шум розпізнавання.** «ЕХ\¥ - склад Продавця» → `EXW`; «Ячмінь Зй клас» → `grade: "3"`; «ЗО днів» → `30`. Якщо OCR не дає однозначного прочитання — `"other"` (008: «ПЭР-Україна» може бути DAP або DDP).
2. **Вільні рядки (`buyer`, `delivery.place`, `delivery.period_raw`) — дослівно з тексту, разом із шумом.** Переноси рядків замінюються пробілом, прийменники на початку відкидаються («за адресою Покупця: вул. …» → «вул. …»). Тому порівнювати рядки в метриках варто нечітко (схожість), а не точним збігом.
3. **`buyer`** — назва покупця/замовника з преамбули, без «в особі …».
4. **Додаткові угоди й специфікації** — частина тексту; значення з них рахуються.

## Поля

| Поле | Рішення |
|---|---|
| `crop` | культура товару; насіння кукурудзи → `corn`; кілька культур у договорі («кукурудзи та/або соняшнику») → `other` |
| `quantity_t` | лише в тоннах або кілограмах (10 000 кг → `10.0`); посівні одиниці (п.о.), мішки → `null` |
| `tolerance` | лише допустиме відхилення **обсягу** («±5%, на вибір продавця»). «Зернова домішка не більше 10%» — це якість, не толеранс |
| `price.amount_per_t` | ціна за тонну, з кг переводиться (6,50 грн/кг → `6500.0`); названо за тонну і без ПДВ, і з ПДВ → з ПДВ; з ПДВ лише загальна сума договору → ціна без ПДВ; загальна сума ÷ кількість **не рахується**; ціна за п.о. → `null` |
| `price.currency` | валюта цін у тексті, навіть якщо ціна не за тонну (004) |
| `price.vat_included` | стосується саме `amount_per_t`: «з ПДВ» → `true`; «без ПДВ» або ПДВ не згадано → `false`; немає `amount_per_t` → `null` |
| `basis` | лише названий Incoterms (`EXW`, `FCA`, …). Умова поставки без терміна («за рахунок постачальника», «самовивіз зі складу», «ціна включає доставку») → `other`. Лише адреса місця поставки → `null` |
| `delivery.place` | з пункту про місце поставки, дослівно; «до Замовника» без адреси → `null` |
| `delivery.date_from/date_to` | конкретні дати поставки (`"2022-12-31"`). **Строк дії договору — не строк поставки** |
| `delivery.period_raw` | відносний строк дослівно («протягом 5 робочих днів з дня підписання…»), лише коли конкретних дат поставки немає |
| `payment.days` | число днів на оплату; фіксована дата («до 05.10.2018») → `days: null`, `trigger: other` |
| `payment.days_type` | «календарних» → `calendar`, «банківських» → `banking`, «робочих» → `other`, не сказано → `null` |
| `payment.trigger` | від чого рахується строк: аванс/передплата → `prepayment`; «після отримання Товару (на підставі накладної)» → `after_delivery`; «з дати підписання накладних / отримання рахунку» → `after_documents` |
| `payment.vat_after_registration` | лише якщо прямо пов'язано оплату ПДВ з реєстрацією податкової накладної; обов'язок продавця зареєструвати накладну — ще не це |
| `penalties` | кожна санкція окремим елементом. Пеня і штраф в одному пункті — дві санкції. Разовий штраф (без «за кожен день») → `one_time_pct`; «за кожен день» → `pct_per_day`; «облікової ставки НБУ» → `nbu_rate_multiple`, `amount: 1`, «подвійної» → `2`; «% річних» або «за кожну годину» → `other` |
| `penalties[].trigger` | прострочення поставки → `late_delivery`; прострочення оплати → `late_payment`; недопоставка → `under_delivery`; якість, заміна товару, відмова від постачання, податкові порушення, зміна ціни → `other` |
| `penalties[].cap_pct` | лише прямо написаний максимум («не більше 10%») |
| Не санкції | відшкодування збитків без розміру; повернення передплати з % річних при форс-мажорі |
| `quality.grade` | клас як написано («3-го класу» → `"3"`, «фуражної» → `"фураж"`), також для кукурудзи й ячменю |
| `quality.*_max/_min` | лише прямо названі показники; «смітна домішка» → `foreign_matter_max`; посилання на ДСТУ без чисел → `null` |
| `quality.lab` | хто визначає якість: державна інспекція (ДІСХ), незалежний випробувальний центр → `independent`; лише сертифікат виробника → `null` |

## Власні договори автора (`own_001–007`)

**Стан:** чернетку всіх 7 файлів підготував Claude Opus 5.5 (20.10.2026); автор дозаповнив, перевірив і виправив кожне поле. У `evidence` для кожного поля вказано пункт договору. Договори однакового шаблону, тому рішення нижче однакові для всіх:

1. **`buyer`** — назву покупця автор приховав (`“ ”`, «назва покупця») → `null`.
2. **Ціна «X грн плюс ПДВ Y, разом Z»** → `amount_per_t = Z`, `vat_included = true`. Ціна без згадки ПДВ (постачальник — ФОП, 004) → `vat_included = false`.
3. **Кілька класів із різними цінами** (003: 2/3/4 клас) → `grade` і `amount_per_t` = `null`; показники, однакові для всіх класів (вологість, смітна домішка), заповнюються, решта (протеїн лише для 2 класу) → `null`.
4. **«у термін до 07.07.2026»** → лише `date_to`; «у період з … по/до …» → обидві дати.
5. **Лабораторія** — виробничо-технологічна лабораторія елеватора чи терміналу в місці поставки (за рахунок покупця) → `lab: other`.
6. **Оплата** «протягом 3 банківських/робочих днів з дати передачі права власності та отримання документів» → `days: 3`, `trigger: after_documents`; «робочих» → `days_type: other`. ПДВ-частина після реєстрації податкової накладної (п. 6.3–6.4) → `vat_after_registration: true`.
7. **Санкції:** пеня покупця «подвійної облікової ставки НБУ за кожен день» → `late_payment`, `nbu_rate_multiple`, `2`; штраф 30% «за непостачання/недопостачання» → `under_delivery`, `one_time_pct`; штраф «3 долари США за тонну» за фумігаційні гази → `trigger: other`, `unit: other`; «25% річних» за неповернення передоплати (не форс-мажор) → `trigger: other`, `unit: other`. Відшкодування збитків без розміру — не санкція.
8. **Маски** (`[ЄДРПОУ]`, `[АДРЕСА]`, `[ПРИХОВАНО]`) у місці поставки — частина тексту; у `delivery.place` береться рядок до маски коду.

## Персональні дані

Тексти генерує `scripts/pdf_to_text.py`. Під час розмітки знайдені пропуски маскування додано в `data/raw/prozorro/extra_names.txt` (ім'я, розпізнане латиницею; прізвище великими літерами без по батькові; прізвище, розбите пробілами) і `data/raw/prozorro/extra_addresses.txt` (адреси ФОП). Обидва файли поза git.

У власних договорах автор прибрав назви й комерційні дані ще в PDF; `pdf_to_text --prefix own_` додатково ховає всі 8-значні коди підприємств (`[ЄДРПОУ]`), адреси сторін зі списку `data/raw/own/extra_addresses.txt` (`[АДРЕСА]`) і рядки зі списку `data/raw/own/extra_hidden.txt` — назву постачальника в першому рядку (`[ПРИХОВАНО]`). Обидва списки поза git.
