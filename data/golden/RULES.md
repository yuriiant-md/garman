# Правила розмітки golden set

Еталон — це те, що уважна людина може прямо прочитати **в тексті `data/texts/…txt`** (не в PDF), за тими самими правилами, що й у промпті: немає в тексті → `null`, умова є, але не з дозволених варіантів → `"other"`.

**Хто розмічав.** Розмітку всіх 28 договорів (`prozorro_001–010`, `own_001–018`) затвердив автор: перевірив кожне поле за текстом і виправив спірні значення. Класи й показники якості (`grades`, 25.10.2026) — за правилами розділу «Класи й показники якості», так само з перевіркою автора.

## Загальні

1. **Enum, числа, дати — за змістом, крізь шум розпізнавання.** «ЕХ\¥ - склад Продавця» → `EXW`; «Ячмінь Зй клас» → `grade: "3"`; «ЗО днів» → `30`. Якщо OCR не дає однозначного прочитання — `"other"` (008: «ПЭР-Україна» може бути DAP або DDP).
2. **Вільні рядки (`buyer`, `delivery.place`, `delivery.period_raw`) — дослівно з тексту, разом із шумом.** Переноси рядків замінюються пробілом, прийменники на початку відкидаються («за адресою Покупця: вул. …» → «вул. …»). Тому порівнювати рядки в метриках варто нечітко (схожість), а не точним збігом.
3. **`buyer`** — назва покупця/замовника з преамбули, без «в особі …».
4. **Додаткові угоди й специфікації** — частина тексту; значення з них рахуються.

## Поля

| Поле | Рішення |
|---|---|
| `crop` | культура товару; насіння кукурудзи → `corn`; кілька культур у договорі («кукурудзи та/або соняшнику») → `other` |
| `quantity_t` | лише в тоннах або кілограмах (10 000 кг → `10.0`); посівні одиниці (п.о.), мішки → `null` |
| `tolerance` | лише допустиме відхилення **обсягу** («±5%, на вибір продавця»). «Зернова домішка не більше 10%» — це якість, не толеранс |
| `grades[].amount_per_t` | ціна за тонну **свого класу**, з кг переводиться (6,50 грн/кг → `6500.0`); названо за тонну і без ПДВ, і з ПДВ → з ПДВ; з ПДВ лише загальна сума договору → ціна без ПДВ; загальна сума ÷ кількість **не рахується**; ціна за п.о. → `null` |
| `price.currency` | валюта цін у тексті, навіть якщо ціна не за тонну (004) |
| `price.vat_included` | стосується цін класів (`grades[].amount_per_t`): «з ПДВ» → `true`; «без ПДВ» або ПДВ не згадано → `false`; жодної ціни за тонну → `null` |
| `basis` | лише названий Incoterms (`EXW`, `FCA`, …). Умова поставки без терміна («за рахунок постачальника», «самовивіз зі складу», «ціна включає доставку») → `other`. Лише адреса місця поставки → `null` |
| `delivery.place` | з пункту про місце поставки, дослівно; «до Замовника» без адреси → `null` |
| `delivery.date_from/date_to` | конкретні дати поставки (`"2022-12-31"`). **Строк дії договору — не строк поставки** |
| `delivery.period_raw` | відносний строк дослівно («протягом 5 робочих днів з дня підписання…»), лише коли конкретних дат поставки немає |
| `payment.days` | число днів на оплату; фіксована дата («до 05.10.2018») → `days: null`, `trigger: other` |
| `payment.days_type` | «календарних» → `calendar`, «банківських» → `banking`, «робочих» → `other`, не сказано → `null` |
| `payment.trigger` | від чого рахується строк: аванс/передплата → `prepayment`; «після отримання Товару (на підставі накладної)» → `after_delivery`; «з дати підписання накладних / отримання рахунку» → `after_documents` |
| `payment.vat_after_registration` | лише якщо прямо пов'язано оплату ПДВ з реєстрацією податкової накладної; обов'язок продавця зареєструвати накладну — ще не це |
| `penalties` | кожна санкція окремим елементом. Пеня і штраф в одному пункті — дві санкції. Разовий штраф (без «за кожен день») → `one_time_pct`; «за кожен день» → `pct_per_day`; «облікової ставки НБУ» → `nbu_rate_multiple`, `amount: 1`, «подвійної» → `2`; «% річних» або «за кожну годину» → `other` |
| `penalties[].trigger` | прострочення поставки → `late_delivery`; прострочення оплати → `late_payment`; недопоставка → `under_delivery`; якість, заміна товару, відмова від постачання, податкові порушення, зміна ціни → `other` |
| `penalties[].cap_pct` | лише прямо написаний максимум («не більше 10%») |
| Не санкції | відшкодування збитків без розміру; повернення передплати з % річних при форс-мажорі |
| `grades[].grade` | клас як написано («3-го класу» → `"3"`, «фуражної» → `"фураж"`), також для кукурудзи й ячменю. Кожен клас — окремий елемент `grades` зі своєю ціною й показниками; ціна чи показники без класу → один елемент із `grade: null`; немає ні ціни, ні класу, ні показників → `grades: null` |
| `grades[].indicators` | показники якості свого класу — правила в розділі «Класи й показники якості» нижче; посилання на ДСТУ без чисел → показника немає |
| `quality.lab` | чия лабораторія визначає якість: державна інспекція (ДІСХ), незалежний випробувальний центр → `independent`; лише сертифікат виробника → `null`. Хто платить за аналізи — не лабораторія, а `analysis_paid_by` |
| `quality.analysis_paid_by` | хто платить за аналізи якості: «за рахунок Покупця» / «Продавця» → `buyer` / `seller`; оплата лише арбітражної проби чи експертизи у спорі або за неякісний товар — не це → `null` (prozorro_007); не сказано → `null` |

## Класи й показники якості (`grades[].indicators`)

1. **Що таке показник.** Рядок таблиці чи переліку якості з порогом: «за винятком: …» (п. 2.1 у власних договорах), «Сторони погодили такі якісні показники» (prozorro_001). Загальні вимоги («здоровий», «нормальний запах», зараженість за ГОСТ, ГМО в загальному абзаці) — не показники. ГМО в переліку погоджених показників — показник (`other`).
2. **Назва і значення — обидва з тексту.** Значення без назви («мін. 250 c.», хоча з одиниці зрозуміло, що це число падіння) і назва без значення («Кл / мі / Пр / мі») не беруться, навіть якщо їх легко відновити з шаблону (own_003, own_005). Назва з шумом розпізнавання, яку однозначно видно, береться («смі гієна домішка» → `foreign_matter`, «11 асі пня амброзії» → `ragweed`).
3. **Межа.** «не менше», «мін.» → `min`; «не більше», «макс.» → `max`; «НЕ допускається» → `max`, `value: 0`, `unit: pct`.
4. **Одиниця.** % → `pct`; г/л → `g_per_l`; секунди (число падіння) → `seconds`; ІДК → `units`; шт/кг → `pcs_per_kg`.
5. **«В т.ч.» — окремий показник.** «Зернова домішка макс. 6% (в т.ч. пророслі зерна макс. 1%)» → `grain_admixture` 6 і `sprouted` 1; «Пошкоджені зерна (в тому числі ушкоджені під час сушіння) макс. 5% (макс. 2%)» → `damaged` 5 і `other` 2.
6. **Назва → `name`.** Вологість → `moisture`; сміттєва (смітна) домішка → `foreign_matter`; зернова домішка → `grain_admixture`; протеїн → `protein`; клейковина → `gluten`; ІДК → `gluten_deformation`; число падіння → `falling_number`; натура, натурна вага → `test_weight`; зерна, пошкоджені клопом-черепашкою → `bug_damaged`; пророслі зерна → `sprouted`; сажкове зерно → `smut`; фузаріозне зерно → `fusarium`; биті зерна → `broken`; пошкоджені зерна → `damaged`; амброзія, насіння амброзії → `ragweed`. Решта → `other`, а `raw_name` — назва дослівно, без пояснення в дужках: «Зерна злакових культур, що за характером пошкоджень не віднесені до смітної домішки», «Сажка всіх видів, ріжки», «ГМО». Для відомих назв `raw_name: null`.
7. **Показник належить класу, під яким стоїть; спільних немає.** Якщо значення для якогось класу нечитабельне, у цього класу показника немає, навіть коли в сусідніх класах воно однакове (own_003: вологість 3 класу).

## Власні договори автора (`own_001–007`, `own_013–018`)

**Стан:** `own_001–007` (20.10.2026) — автор дозаповнив, перевірив і виправив кожне поле; `own_013–018` (договори 2024–2026 рр., 26.10.2026) — автор перевірив і затвердив кожне поле. У `evidence` для кожного поля вказано пункт договору. Договори однакового шаблону, тому рішення нижче однакові для всіх:

1. **`buyer`** — назву покупця автор приховав (`“ ”`, «назва покупця») → `null`.
2. **Ціна «X грн плюс ПДВ Y, разом Z»** → `amount_per_t = Z`, `vat_included = true`. Ціна без згадки ПДВ (постачальник — ФОП, 004) → `vat_included = false`.
3. **Кілька класів із різними цінами** (003: 2/3/4 клас) → три елементи `grades`, кожен зі своєю ціною «разом» (п. 4.1) і своїми показниками (п. 2.1); `vat_included = true`.
4. **«у термін до 07.07.2026»** → лише `date_to`; «у період з … по/до …» → обидві дати.
5. **Лабораторія** — виробничо-технологічна лабораторія елеватора чи терміналу в місці поставки → `lab: other`; «за рахунок Покупця» (п. 2.3) — хто платить, а не чия лабораторія → `analysis_paid_by: buyer`.
6. **Оплата** «протягом 3 банківських/робочих днів з дати передачі права власності та отримання документів» → `days: 3`, `trigger: after_documents`; «робочих» → `days_type: other`. ПДВ-частина після реєстрації податкової накладної (п. 6.3–6.4) → `vat_after_registration: true`.
7. **Санкції:** пеня покупця «подвійної облікової ставки НБУ за кожен день» → `late_payment`, `nbu_rate_multiple`, `2`; штраф 30% «за непостачання/недопостачання» → `under_delivery`, `one_time_pct`; штраф «3 долари США за тонну» за фумігаційні гази → `trigger: other`, `unit: other`; «25% річних» за неповернення передоплати (не форс-мажор) → `trigger: other`, `unit: other`. Відшкодування збитків без розміру — не санкція.
8. **Маски** (`[ЄДРПОУ]`, `[АДРЕСА]`, `[ПРИХОВАНО]`) у місці поставки — частина тексту; у `delivery.place` береться рядок до маски коду.
9. **«ячмінь фуражний, 3-го класу»** (014, 017) → `grade: "3"`: номер класу точніший, «фуражний» тут — призначення, як «м'яка» в пшениці. «Фуражний» без номера → `"фураж"` (як `own_010`). Таблиця ячменю: «Егілопс циліндричний (Aegilops cylindrica) – НЕ допускається» → `other`, `max`, `0`, `raw_name` без латинської назви в дужках; «Зерна пшениці незалежно від характеру пошкоджень» → `other`; «всі інші показники – відповідно до ДСТУ» — не показник.
10. **«86% передоплати … протягом 3 робочих днів з моменту надання документів»** (014, 015) → `trigger: after_documents`, як правило 6 і `own_005/007`: строк рахується від документів, слово «передоплата» цього не змінює.
11. **Неустойка постачальника «подвійної облікової ставки НБУ … за кожен день прострочення» за несвоєчасну поставку** (017, 018) → `late_delivery`, `nbu_rate_multiple`, `2`.

## Договори загального шаблону (`own_008–012`)

**Стан:** тексти написав автор за загальним шаблоном договору поставки; назви сторін, коди, рахунки й адреси вигадані. Розмітку автор перевірив і виправив (25.10.2026). Шаблон інший, ніж у `own_001–007`, тому й рішення свої:

1. **`buyer`** — повна назва з преамбули, як у Prozorro («Товариство з обмеженою відповідальністю «…»»); іноземний покупець — як написано («Alpine Commodities SA», 010).
2. **`delivery.place`** — місце, назване після терміна Incoterms у п. 3.1: для CPT і DAP — місце призначення, для FCA і FOB — місце завантаження. Примітки шаблону «(умовна)», «(адреса умовна)» не беруться.
3. **«Період відвантаження / поставки: з … по …»** → обидві дати.
4. **Оплата частинами** (аванс 30% + залишок, 90% + 10%) → `days`, `days_type`, `trigger` — за більшою частиною, як 86% у `own_005/007`; аванс окремо не розмічається.
5. **Строк оплати від отримання документів, серед яких *зареєстрована* податкова накладна** → `vat_after_registration: true`: увесь платіж, разом із ПДВ, чекає реєстрації. Просто «податкова накладна» без «зареєстрованої» → `null` (009).
6. **Акредитив «за пред'явлення документів»** → `trigger: after_documents`, `days: null`; строк відкриття акредитива — не строк оплати (010).
7. **Ціна за формулою** (Ц = Р − Д, 012) → `amount_per_t: null`, `price.currency` — валюта формули, `vat_included: null`; приклад з умовними значеннями — не ціна.
8. **Клас:** «фуражна», «фуражний» → `"фураж"`; «продовольча» без номера класу → `grade: null` (011).
9. **Санкції:** пеня «0,1% … але не більше подвійної облікової ставки НБУ» → `pct_per_day`, `0.1`, `cap_pct: null` (межа не у % від суми); «винна Сторона» → `payer: other` (009); несвоєчасне відкриття акредитива (010) і неприйняття товару покупцем (012) → `trigger: other`. Різниця з ринковою ціною і збитки за дефолтом GAFTA — без розміру, не санкції.
10. **Лабораторія:** «незалежний інспектор або акредитована лабораторія» → `independent`; «акредитована лабораторія» без власника → `independent` (009); «лабораторія Покупця» → `buyer`, навіть коли для спору є незалежна (011).
11. **Таблиця якості:** рядок із порогом «не допускається» чи «відсутні» («Зараженість шкідниками», «Живі шкідники») → `other`, `max`, `0`, `pct` (правила 1 і 3 розділу «Класи й показники якості»). «Мікотоксини у межах нормативів» і «Запах і колір» — без числа, не показники. Дезоксиніваленол (ДОН) у мг/кг → `other`, `unit: other`, `raw_name` без «(ДОН)». Знижки до ціни за якість (п. 2.2) — не показники.

## Персональні дані

Тексти генерує `scripts/pdf_to_text.py`. Під час розмітки знайдені пропуски маскування додано в `data/raw/prozorro/extra_names.txt` (ім'я, розпізнане латиницею; прізвище великими літерами без по батькові; прізвище, розбите пробілами) і `data/raw/prozorro/extra_addresses.txt` (адреси ФОП). Обидва файли поза git.

У власних договорах автор прибрав назви й комерційні дані ще в PDF; `pdf_to_text --prefix own_` додатково ховає всі 8-значні коди підприємств (`[ЄДРПОУ]`), адреси сторін зі списку `data/raw/own/extra_addresses.txt` (`[АДРЕСА]`) і рядки зі списку `data/raw/own/extra_hidden.txt` — назву постачальника в першому рядку (`[ПРИХОВАНО]`). Обидва списки поза git.

У `own_008–012` дані вигадані, але скрипт однаково ховає коди, IBAN, email і ПІБ. Ім'я іноземного директора латиницею (010) він не ловить; воно теж вигадане, тож лишилося в тексті.
